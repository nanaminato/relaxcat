# Excel 样式优化：后续改进计划

> Status: Proposal
>
> 本文仅记录后续改进方向，不修改当前实现。

## 背景

当前 Excel 样式优化第一版主要针对 `xl/styles.xml` 中的 `cellXfs` 做完全重复项去重，并同步更新工作表中的样式索引。该方案安全、可验证，但实际工作簿测试表明：`cellXfs` 数量下降并不一定意味着 `styles.xml` 会明显缩小。

例如某次实际处理结果中，`cellXfs` 从 184 降至 179，但 `styles.xml` 仍约为 9.35 MB。这说明文件膨胀的主体可能位于 `fonts`、`fills`、`borders`、`cellStyleXfs`、`dxfs` 等底层样式组件，而非 `cellXfs` 本身。

因此后续优化不应只关注最终的单元格格式表，而应增加对整个 OOXML 样式图的诊断、引用分析、去重与垃圾回收能力。

## 1. 增加 styles.xml 分区诊断

分析阶段应分别统计以下分区：

- `numFmts`
- `fonts`
- `fills`
- `borders`
- `cellStyleXfs`
- `cellXfs`
- `cellStyles`
- `dxfs`
- 其它样式相关分区

除元素数量外，建议同时计算：

- XML 大小或近似序列化大小；
- 被引用元素数量；
- 未引用元素数量；
- 完全重复元素数量；
- 各分区占整个 `styles.xml` 的比例。

界面可展示类似：

```text
styles.xml                  9.35 MB
├─ borders                  8.91 MB   95.3%
├─ dxfs                   280.4 KB    2.9%
├─ cellXfs                 72.1 KB    0.8%
├─ fonts                   48.2 KB    0.5%
└─ others                  45.3 KB    0.5%
```

这样可以在执行优化前直接识别真正造成文件膨胀的分区，避免仅根据 `cellXfs` 数量判断优化空间。

## 2. 底层样式组件去重

后续版本可在严格等价的前提下扩展去重范围：

1. 对 `fonts`、`fills`、`borders` 等组件生成规范化结构键；
2. 只合并规范化定义完全一致的组件；
3. 为每个分区建立 `oldId -> newId` 映射；
4. 重建引用这些组件的 `cellXfs` / `cellStyleXfs`；
5. 再对重建后的 XF 做第二轮完全重复项去重。

建议第一阶段仍坚持“结构完全等价才合并”，不要直接进行视觉等价或语义等价合并，以降低破坏 Excel 格式的风险。

## 3. 样式引用图与垃圾回收

仅修改工作表中的 `s` 索引不足以保证 `styles.xml` 缩小。旧 XF 或底层组件即使已经不再被工作表直接使用，也可能继续保留在样式表中。

建议建立完整的样式引用图，例如：

```text
worksheet c/row/col
        ↓
     cellXfs
        ↓
 ┌──────┼────────┐
font   fill     border
        ↓
  other style relations
```

在能够证明引用关系完整的前提下，对不可达定义执行类似垃圾回收（GC）的处理：

- 删除未引用 `cellXfs`；
- 删除未引用 `fonts`；
- 删除未引用 `fills`；
- 删除未引用 `borders`；
- 更新所有受影响 ID；
- 更新各分区 `count`。

需要特别检查命名样式、条件格式、差分格式、表格、数据透视表及其它可能间接引用样式的 OOXML 部件。无法证明安全的定义应继续保留。

## 4. 推荐的优化流水线

```text
读取 styles.xml
    ↓
建立完整引用关系
    ↓
底层组件完全重复项去重
(fonts / fills / borders / ...)
    ↓
重映射 XF 中的组件 ID
    ↓
cellXfs / cellStyleXfs 去重
    ↓
重映射 worksheet 样式索引
    ↓
安全的不可达样式 GC
    ↓
重新生成 styles.xml
    ↓
结构、引用、外观与包完整性校验
```

## 5. 分阶段实现建议

### Phase 1：诊断增强

只读，不改变优化行为：

- 显示各样式分区数量；
- 显示各分区大小占比；
- 统计重复数、引用数和未引用数；
- 明确指出主要膨胀来源。

这是优先级最高且风险最低的改进。

### Phase 2：底层完全重复项去重

优先处理引用关系相对清晰的：

- `fonts`
- `fills`
- `borders`

要求更新所有引用并增加对应校验。

### Phase 3：安全 GC

在引用图覆盖充分后，删除能够证明不可达的样式定义。无法确认是否存在隐藏依赖时必须保留。

### Phase 4：高级规范化（可选）

未来可研究“XML 不同但 Excel 渲染效果等价”的样式合并，但该模式风险显著高于完全重复项去重，应作为独立的高级/实验性优化模式，而不是默认行为。

## 6. 校验要求

扩展优化范围后，应至少验证：

- 所有 XF 中的 `fontId` / `fillId` / `borderId` 等引用均有效；
- 所有工作表样式索引均有效；
- `count` 与实际子元素数量一致；
- 优化前后实际使用样式的结构/外观等价；
- 非目标 OOXML 部件不发生意外变化；
- `.xlsm` 中 VBA 等二进制部件保持原样；
- 输出工作簿能够被 Excel 正常打开且无需修复。

## 目标

后续 Excel 样式优化的衡量指标不应只是“减少多少个 `cellXfs`”，而应同时关注：

- `styles.xml` 实际减少量；
- XLSX/XLSM 最终文件减少量；
- 重复底层组件减少量；
- 不可达样式定义减少量；
- 工作簿格式与行为是否保持不变。

最终目标是在保持当前保守、安全策略的基础上，从“单元格 XF 去重器”逐步扩展为完整的 OOXML 样式诊断与安全压缩工具。
